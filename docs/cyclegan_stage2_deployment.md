# CycleGAN 四阶段迭代：第二阶段

本文保留 `c31d0db` 的阶段二基线及历史位流证据。后续控制和调试寄存器优化见 [第二阶段资源优化](cyclegan_stage2_resource_optimization.md)，当前板级签名为 `0xe313`。

接续第一阶段提交 `397a3cd`，实现 RGB 输入、三层编码与九个残差块的自主 FPGA 调度。使用相同 epoch11 权重和固定 BN，目标为 Ti60F225 C4，计算时钟 150 MHz、DDR 用户时钟 96 MHz。阶段三的转置卷积和阶段四的 7×7 输出尚未接入。

本阶段已完成原生整帧仿真、两次下载后的六帧上板验收和资源/时序验证。最终机器证据见 [cyclegan_stage2_deployment.json](analysis/cyclegan_stage2_deployment.json)，记录源码、位流、实际编译副本、报告及回读结果的 SHA256。

## 调度与存储

`cyclegan_encoder` 的 `RESIDUAL_ENABLE` 默认关闭，保留第一阶段的使用方式。开启后，编码完成即交接给 `cyclegan_residual_scheduler`，两个调度器共用同一个 `mobilenet_unit`、原有四深指令 FIFO、100 个 DSP 和原有 feature cache。

残差输入和输出均为 32×30×40，按 `base + channel*12 + tile_y*4 + tile_x` 排列，每份 384 个 10×10 tile。

| 地址 | 残差阶段用途 |
|---|---|
| 1056～1439 | 编码输出，供第一个块作为 DW 与 skip 输入 |
| 0～383 | 第 1、3、5、7、9 块输出 |
| 384～767 | 第 2、4、6、8 块输出 |
| 1440～1471 | 32 通道 DW/BN 中间结果 |
| 1472 | 单通道 PW/BN 临时结果 |

原 RGB 和编码 ring 在编码结束后已无读者，直接复用为两份残差特征缓存。没有增加 feature BRAM，不搬运整层特征，也不在残差期间读写 DDR。DW 使用 `tile_pitch=1,row_pitch=4`、3×3 零填充和整帧边界标志，无需重排。

每个空间 tile 连续提交 32 组 DW→固定 BN/ReLU，再提交 32 组 PW→固定 BN→ADD，共 160 条指令。PW 读取连续的 32 通道 DW 临时区；ADD 从对应输入地址读取 skip，输出饱和到 Q4.4，不加额外舍入。其他算子保留原整数参考的舍入方式。

每块包含 12 个空间 tile、1920 条指令，九块共 17280 条；连同编码共 45696 条。生产者在 FIFO 有空位时立即生成下一条指令。块末尾等待全部指令执行完成，再交换输入/输出区域，保证 DW 的跨 tile 邻域和 skip 在最后一个读者完成前不被覆盖。地址乘 9/12/32 使用常量移位与加法，没有配置地址计算 DSP。

## 参数与资源

`RESIDUAL_PREFIX=1` 选择精确的前 14027 个 Q8.8 参数词，覆盖三层编码和九个残差块，并关闭 Tanh 路径。`mn_residual_rom.sv` 由资产工具生成，以 14 块低 10 位平面和 2 块符号平面保存数据；超出紧凑范围的词通过少量精确例外恢复。ROM 保持一拍读出和读禁止期间输出保持。

该 ROM 为 16 BRAM，比完整模型的 25 BRAM 少 9 块。与阶段一的 3 BRAM ROM 相比，板级总 BRAM 只增加 13 块；其余增加的是调度、状态计数和验收探针逻辑。

| 板级综合项目（包含 DDR/JTAG） | 阶段一 | 阶段二 |
|---|---:|---:|
| LUT4 | 17304 | 18078 |
| FF | 11967 | 12592 |
| DSP48 | 100 | 100 |
| DSP24 | 0 | 0 |
| RAM10 | 30 | 43 |
| DPRAM10 | 168 | 168 |
| BRAM 总数 | 198 | 211 / 256 |
| 150 MHz 计算时钟 setup / hold | 0.937 / 0.035 ns | 0.955 / 0.026 ns |

全部已分析时钟关系的 setup 和 hold 余量均非负。表中的时序余量专指计算时钟，完整时钟关系保存在机器证据中。

## 验收方式

板级签名 `0xe312`。命令 3 的最低位选择逐块暂停，0 为连续九块自主运行。暂停只发生在整块完成、FIFO 排空且计算单元空闲后；命令 4 可回读输出 cache，命令 7 继续下一块。暂停/继续通过 toggle 同步跨越 96/150 MHz 时钟域，回读期间不提交计算指令。正常模式不需要主机在块间下发命令。

`cycles` 排除显式验收暂停；`residual_cycles` 只累计各块执行和排空阶段，`block_cycles` 保留最近完成块的时间。编码的数据等待和整个前缀的指令供应等待另行计数。暂停回读的墙钟耗时不作为推理时间。

原生测试使用真实厂商 DSP/BRAM 模型，检查三层编码的 268800 个池化值和九块 ADD 写回的 345600 个值。暂停模式另逐块回读全部 tile，检查暂停期间周期计数、指令数和计算状态保持不变；连续模式检查同样的全部 ADD 写回。残差阶段 DDR 请求必须为零，总指令数必须为 45696。

普通/反色输入的原生整帧测试均通过：每块 49155 拍，九块 442395 拍，即 2.9493 ms；编码 622993 拍，整个前缀 1065400 拍。计算单元忙时间（信号名 `mac_cycles`，含装窗和后处理）962640 拍，指令供应等待 0，编码数据等待 56857 拍。45 拍基础 DDR 延迟的连续模式也通过，整个前缀为 1345236 拍，残差时间与指令等待不变。计算单元原有 201 用例、252 条指令和总线回归通过；同一套厂商模型在 ModelSim 下运行，另检查每类指令的执行周期。

保留第一阶段实际 RGB 装载流 CRC32，先确认送入计算单元的数据正确，再判断残差算术输出。板级脚本先下载并对普通/反色两帧回读全部输入 DDR 和九块结果，再重新下载相同位流，运行两帧逐块回读及两帧无暂停连续执行。位流、RTL、实际编译副本、参考结果与回读结果均记录 SHA256。

| 最终上板项目 | 实测结果 |
|---|---|
| 成功帧数 | 两次下载共六帧，普通/反色各三帧 |
| 逐块回读 | 四帧 × 九块 × 38400 值，1382400 值零差异 |
| 无暂停连续模式 | 两帧，各自第九块 38400 值零差异 |
| 全部回读 | 1459200 值零差异，六帧实际 RGB 装载 CRC 全部匹配 |
| 九块残差 | 442395 拍，2.9493 ms；每块 49155 拍 |
| RGB 至残差末尾 | 1298437～1299199 拍，8.6562～8.6613 ms |
| 指令供应等待 | 六帧均为 0 拍 |
| 编码数据等待 | 289894～290656 拍，残差不增加 DDR 等待 |

显式暂停和 JTAG 上传/回读不计入上述推理时间。残差阶段计算单元忙 425088 拍，占其执行阶段的 96.09%；余下为每条指令原有的一拍弹出/交接和块间控制，不增加因指令或 DDR 数据未到而产生的等待。这里的忙计数包含装窗和后处理，不等同于 DSP 乘加占空比。

### 本板 DDR 相位配置

初版上板虽然整帧 DDR 静态回读正确，但实际装载 CRC 错误，编码输出也已有差异。扩大为四拍读取仍失败，已撤回，保留三拍突发及原读桥响应稳定期。该问题发生在残差运算之前。

阶段二板壳保留 DDR IP 的校准流程，在校准结束后向动态相位接口提交相位 6，再开放帧传输。命令 5 的 bit3 可启用手动对照，bits2:0 指定相位；VIO 同时记录 IP 校准选择和板壳使用的相位。这是当前板卡和 384 MHz DDR 配置的实测配置，后续更换板卡或 DDR 时钟需重新验证。

`-PhaseControl` 在同一位流中先将相位设为 5，复现实际输入 CRC 错误，再设为 6 进行完整验收。最终机器证据同时保留失败候选与通过结果，避免把静态 DDR 回读或单次校准通过当成完整推理验收。

最终位流的 IP 校准选择为 6。手动设为 5 时普通帧实际 CRC 为 `b436884a`，预期为 `326d32e8`；同一位流、同一次下载切回 6 后普通/反色两帧全部九块通过，重新下载后默认相位 6 的四帧也通过。该对照支持使用当前相位配置，仍由每帧 CRC 和逐值回读承担数值验收。

## 复现

```powershell
./scripts/run_residual_modelsim.ps1
./scripts/run_residual_modelsim.ps1 -Inverted
./scripts/run_residual_modelsim.ps1 -DdrDelay 45 -Continuous
./scripts/run_residual_board.ps1 -Program -RepeatBoot -PhaseControl
./scripts/run_unit_modelsim.ps1
python tools/record_residual_deployment.py
```

构建和仿真使用 TEMP 下的 ASCII 副本，阶段二报告与回读保存于 `build/stage2`，阶段一证据保持为其历史提交的记录。参考工程只读。资产准备仍依赖本机已经导出的 epoch11 参数和两帧整数参考。

本阶段最终输出位于 0～383，可直接作为第三阶段第一层转置卷积的输入。第三阶段需要分别验证四相交错、扩展后特征容量与 DDR 调度，不能沿用本阶段结果代替验收。
