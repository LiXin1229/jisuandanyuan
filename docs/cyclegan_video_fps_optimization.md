# 实时 CycleGAN 帧率优化

本轮以 `59a84f0` 的实时视频版本为基线，保留 320×240 输入、完整网络、参数、量化和固定归一化。优化只涉及视频顶层的帧调度与计算 PLL；计算单元的 22 个 RTL 文件仍与 `ac1fbbc` 一致。

## 消除串行等待

原流程为“原图拷贝 → 网络计算 → 等待 HDMI VSYNC → 下一帧”。结果模式下约 48.7 ms 计算加 2.3 ms 拷贝超过三个 60 Hz 周期，两个输出槽又要求显示确认后才能开始下一帧，实际吞吐约 15 fps。

现在网络完成后即可获取下一张输入并启动编码。前一帧仍等待 VSYNC 时，下一帧使用独立输入槽、片上 feature cache 和 DDR 中间特征区 3/4/5 MiB 计算。确认到来后才启动配对原图拷贝；原图拷贝与网络计算重叠。

最终输出写入 6/7 MiB 前必须等原图拷贝完成。`output_bank_ready` 经两级同步进入计算域，同时控制最终输出的 valid/ready，未获所有权时保留请求并施加背压。网络中间特征的写入不受该条件限制。结果发布仍要求所有最终 DDR B 响应完成，显示仍只在 VSYNC 切换，输入仍保持 READING 至整网完成。

两个输入槽、两个结果槽、两个配对原图槽、DDR 仲裁器及 HDMI 行缓存全部复用，没有增加整帧缓存或计算通道。

## 时钟与资源

计算 PLL 输出分频从 16 调整为 14，计算时钟从 150 MHz 提至 171.428571 MHz；DDR UI 96 MHz、摄像头和 HDMI 时钟保持原配置。先验证了 160 MHz 版本，再采用通过布局布线的下一档分频。最终 setup/hold 余量为 **0.263 / 0.035 ns**，所有已分析时钟关系非负。

`source_manifest.json` 记录实际计算频率，JTAG 工具由它换算计算时间。构建工具烧录成功后保存活动工程路径，避免从旧的 150 MHz 工程读取频率而错误换算。布线报告将周期显示为 5.833 ns，因此显示的 171.438 MHz 与 PLL 实际 2400/14 MHz 略有舍入差异；验收比较周期，容差为报告的半个最小显示单位。

| 资源 | 优化前 | 优化后 | 增量 |
| --- | ---: | ---: | ---: |
| LUT4 | 26,245 | 26,126 | −119 |
| FF | 12,985 | 12,987 | +2 |
| BRAM | 249 | 249 / 256 | 0 |
| DSP48 | 103 | 103 | 0 |

输出槽就绪标志替代原有显示槽寄存器，新增两级跨时钟同步用于安全地解除最终写入背压，FF 净增 2 个；LUT 总量减少约 0.45%。

## 验证范围

视频单元回归覆盖摄像头裁剪、ISP、池化、采集、按键和 HDMI。板级协议仿真在 171.43 MHz 计算时钟下逐字检查两帧输入、配对原图和 460,800 个输出字节。测试刻意将第一帧的 VSYNC 确认延迟到第二帧最终输出请求之后，验证编码已提前开始，而原图拷贝与最终写入均等待所有权；解除延迟后两帧结果正确，整帧丢弃与显示确认正常。

协议模型只验证接口，不包含网络算术。网络数值通过真实摄像头同帧 DDR 回读、原始 checkpoint 重新生成的整数参考以及编码指令模型进行验证。

## 上板结果

两种显示模式分别连续测量 60 秒，再进行软件模式切换及暂停后的稳定计数采样。两种模式均运行完整网络，HDMI 刷新约 60 Hz，表中 FPS 为网络完成帧率。

| 显示模式 | 基线 FPS | 本轮 FPS | 提升 | 观测完成帧数 |
| --- | ---: | ---: | ---: | ---: |
| 网络结果 | 15.04 | **23.07** | **53.4%** | 1,406 |
| 配对原图 | 20.03 | **23.99** | **19.8%** | 1,462 |

合计 2,868 帧，采集 FIFO 溢出、裁剪过载、HDMI 欠载及原图校验错误均为 0，两种模式指令等待计数均为 0。模式切换测试共八次，全部通过。结束后已恢复实体按键控制，VIO 控制值为 0。

结果模式暂停后的单帧样本为计算 43.203 ms、拷贝 3.248 ms、整帧调度 43.203 ms；原图模式为 42.769 / 1.802 / 42.769 ms。样本取自模式切换测试之后，不代表整个测量窗口的平均延迟；整帧计时已覆盖并行拷贝，不再将拷贝时间额外相加。摄像头仍约 60 fps，没有空闲输入槽时丢弃整帧。

真实摄像头帧 3010 的输入 CRC 为 2,595,387,556，与回读原图重新量化后的 CRC 一致。从 epoch11 checkpoint 重新生成直接 scatter 整数参考，再检查编码指令模型的全部 16 个张量；最终 **230,400 个 RGB 字节零差异，最大误差和 MAE 均为 0**。原图和结果的 HDMI 像素校验和分别为 46,298,940 和 62,678,888，均与对应 DDR 数据按两倍缩放计算的校验和一致。

最终码流 SHA256 为 `fc7023ff0a0771268d7ca4cd94394b2a0506c2f7d3bc021d83ee5cbd4699ce67`。完整源码、资源、时序、七项仿真、持续测试及同帧数值证据见 [机器验证记录](analysis/cyclegan_video_fps_optimization.json)。150 MHz 历史基线 JSON 保留不覆盖；当前验证脚本默认写入本轮优化记录。

## 复现

```powershell
./scripts/run_video_modelsim.ps1 -OutputDir build/video_fps_171_verified
./scripts/run_video_modelsim.ps1 -Tests board -OutputDir build/video_fps_171_verified
./scripts/run_video_board.ps1 -OutputDir build/video_fps_171_verified -Program
./scripts/verify_video_board.ps1 -OutputDir build/video_fps_171_verified `
  -RecordPath docs/analysis/cyclegan_video_fps_optimization.json `
  -Baseline docs/analysis/cyclegan_video_deployment.json
```

复用本轮已构建的码流可加 `-ReuseBuild`；复用已采集的同帧可加 `-ReuseCapture`。验证脚本最终恢复实体按键控制。历史 150 MHz 基线及原始接口说明保留在 [实时视频部署记录](cyclegan_video_deployment.md)。
