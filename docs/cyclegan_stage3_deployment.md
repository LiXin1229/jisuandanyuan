# 第三阶段：三层转置卷积

接续 `c8683d8`，复用当前计算单元，完成固定 epoch11 模型的三层转置卷积。归一化沿用 checkpoint 导出的固定 affine 参数；每层仍先对 CONV 累加结果舍入、饱和到 Q4.4，再执行 NORM、舍入、饱和和 ReLU。

本阶段输出为 **8×240×320 的 Q4.4 特征**。四阶段中的最后一阶段为 7×7、3 通道输出及 Tanh，尚未接入本板级前缀。

## 模型与指令

| 转置层 | 输入 C×H×W | 输出 C×H×W | 权重起点 | NORM 起点 | 指令数 |
|---|---|---|---:|---:|---:|
| 1 | 32×30×40 | 16×60×80 | 14027 | 18635 | 25344 |
| 2 | 16×60×80 | 8×120×160 | 18667 | 19819 | 26112 |
| 3 | 8×120×160 | 8×240×320 | 19835 | 20411 | 55296 |

第三阶段合计 **106752 条指令**；从 RGB 开始含三层编码、九块残差的完整前缀为 **152448 条**。

每个输入空间 tile、每个输出通道依次生成四个 10×10 相位，复用已有 `CONV` 与 `NORM` 指令：

| 相位 | kernel 编码 | 核形状 | 每通道参数数 | 写入 20×20 patch 的坐标 |
|---|---:|---|---:|---|
| 0 | 5 | 1×1 | 1 | 偶数行、偶数列 |
| 1 | 0 | 1×2 | 2 | 偶数行、奇数列 |
| 2 | 1 | 2×1 | 2 | 奇数行、偶数列 |
| 3 | 2 | 2×2 | 4 | 奇数行、奇数列 |

同一相位跨输入通道保持 accumulator；最后一个输入通道结束累加并量化。相位之间保持独立的量化和归一化，数值顺序与整数参考一致。

## 缓存和连续调度

| 地址 | 用途 |
|---|---|
| 0～383 | 第九残差块输出，第一转置层直接读取 |
| 512～895 | 后两层输入的三行 ring，128 tile/行 |
| 1424～1431 | 两组四相结果，每组 4 tile |
| 1432～1439 | 两组交错输出，每组 4 tile |

四相结果保存在原有 feature cache。交错器每次取相同位置的五个偶相位像素和五个奇相位像素，拼成一行，使用已有 20-bit 写掩码写入输出 tile；新增像素暂存只有 **2×40 bit**。DDR 写桥只保存一份 **400-bit 半 tile**，等待 DDR B 应答后才释放；没有重复的跨时钟宽数据 bank，也没有增加 feature BRAM。

两个输出槽按通道轮换。下一组卷积可在前一组交错重排、DDR 写回时发射，槽位直到最后一个半 tile 的 B 应答返回才释放。完整层结束必须同时满足指令排空、两槽释放和 DDR 写回完成。

后两层的输入采用三行 ring，预取当前行和下一行，并在计算当前行时提前准备后一行。四种相位核均向右/下取样，上侧和左侧 halo 不进入 MAC，因此将这些无效 halo 置零，允许安全覆盖已消费的上一行。DMA 不覆盖仍被卷积读取的行；仿真检查实际 cache 读写地址碰撞。

计算单元新增默认关闭的 `STREAM_READS` 接口能力。读口仅在本周期没有核心 cache 操作、且滑窗串行装载已经释放源 tile 时授予交错器。滑窗装载需要多拍保持 RAM 输出，不能仅凭 `cache_rd_en==0` 判定读口可复用。原来的普通总线和前两阶段默认访问契约保持兼容。

调度器使用原有四条指令 FIFO。指令供应等待计数只在工作已持续就绪、计算单元空闲且 FIFO 空时累加；数据或输出槽刚释放后的首次补队列归入依赖恢复。数据等待计数表示指令生产者等待预取结果的周期，可能与 FIFO 中已有指令的执行重叠，不等同于全部计算停顿。

## DDR 和板级协议

三层输出分别写入 **0x00300000、0x00400000、0x00500000**，与原有两个 RGB 帧区分开。通道优先的 tile 索引为 `channel * tiles_y * tiles_x + tile_y * tiles_x + tile_x`，每 tile 占 128 byte。

每个 tile 分为两个 64-byte burst，每 burst 的低 50 byte 为有效数据，高 14 byte 为零。第一个半 tile 保存原有 packed tile 的低 400 bit，第二个保存高 400 bit；两次读回的有效部分拼接后与现有 `*_q44_tiles.bin` 完全一致。此 DDR 布局与参考目录中直接 `100 byte + 28 byte padding` 的 `*_ddr.bin` 不同，后续第四阶段必须使用本协议加载。

事务级写仲裁器在呈现 AW 之前选择上传端或 feature 写端，并保持所有权直到 B 握手。两个 RGB 帧槽及下一帧上传能力保留。仲裁仿真同时发起 40 笔事务，在 AW、W、B 通道加入等待，检查地址、数据在反压期间稳定且事务不混合。

板级签名和 UUID 前缀为 **0xe314**，默认 DDR 相位 6。命令 3 的 bit0=1 时，依次在九个残差块和三个转置层结束后暂停；命令 7 恢复。暂停时允许命令 4 回读 cache/统计和命令 6 回读 DDR。bit0=0 时整个前缀自主连续执行。

复用上一阶段的 832-bit VIO 输入和 32-bit 按字统计邮箱。原统计索引 0～12 保留，新增 13=已完成转置层数、14=转置累计周期、15=最近转置层周期；不新增宽统计探针。

## 验证

最终验收结果由 `tools/record_decoder_deployment.py` 核对来源、逐值回读、时序和位流后生成，记录于 [cyclegan_stage3_deployment.json](analysis/cyclegan_stage3_deployment.json)。

最终源码与位流哈希匹配的验收均通过：

- 正常输入从 RGB 开始执行编码、九块残差和三层转置卷积，原生 RTL 仿真检查 **345600 个残差值、844800 个转置值、152448 条指令**；指令供应等待为零。
- 反色输入从第九残差参考启动三层转置卷积，DDR 基础等待提高到 45 个 DDR 时钟，连续执行 **106752 条指令**，检查 **844800 个值**；指令供应等待为零。
- 同一位流两次下载、共四帧板级验收：第一次两帧逐块、逐层暂停回读，并检查全部上传 RGB DDR；第二次两帧不暂停连续执行，回读完整最终特征。累计 **3609600 个值零差异**，其中转置输出 2918400 个、残差输出 691200 个。每帧实际装载 CRC、帧序及全部已回读层的 SHA256 均匹配，四帧指令供应等待均为零。
- 通用计算单元 **201 个用例、252 条指令**和总线回归通过；写仲裁的 40 笔并发事务与反压检查通过。

四帧转置阶段实测约 **25.24 ms**，包括编码、残差和转置的完整前缀约 **33.90 ms**。计算周期来自 FPGA 150 MHz 计数器，不包含 JTAG 上传、暂停回读和主机等待。执行器忙周期为 4547472；该指标包括滑窗装载等指令执行状态，不代表 DSP 在每一拍都进行有效 MAC。

正常整帧原生仿真的转置阶段为 3777785 拍，完整前缀为 4992632 拍；增加 DDR 延迟的反色连续仿真转置阶段为 4176454 拍。数据变慢仍能得到完全一致的结果，预取、缓冲所有权和写回完成判断不依赖固定 DDR 延迟。

整条前缀仿真额外检查：编码/残差运行期间第三阶段保持空闲，不接收共享写回事件；各残差 ADD 匹配整数参考；三个转置层的 844800 个值既在写桥入口检查，也在模拟 DDR 内存中检查；所有半 tile 的 padding 为零；暂停期间计数冻结、FIFO 排空、DDR 已提交。

该隔离检查覆盖本轮发现的集成问题：编码器池化输出也使用 1427/1431 地址，只有转置调度器处于 RUN/DRAIN 时，这些地址的 NORM 写回才属于相位完成。单独从残差参考启动转置层不能覆盖此前缀交互，故正式验收包含从 RGB 开始的完整 RTL 仿真。

## 复现

在当前工程的 PowerShell 执行；依赖本机已有 ModelSim、Efinity 2026.1 和 NumPy Python，不修改参考工程。

```powershell
./scripts/run_decoder_modelsim.ps1 -FullPrefix
./scripts/run_decoder_modelsim.ps1 -Inverted -DdrDelay 45 -Continuous
iverilog -g2012 -s tb_cyclegan_write_arbiter -o build/stage3/arbiter.vvp rtl/cyclegan_write_arbiter.sv sim/tb_cyclegan_write_arbiter.sv
vvp build/stage3/arbiter.vvp > build/stage3/arbiter.log
./scripts/run_unit_modelsim.ps1
./scripts/run_decoder_board.ps1 -Program -RepeatBoot
python tools/record_decoder_deployment.py
```

最终构建、位流、完整回读及日志位于 **build/stage3_verified**，`staging_path.txt` 指向实际 ASCII 编译副本。参数及参考向量位于 `build/stage3`。历史第一、第二阶段和本轮失败候选保留，未推送远程。
