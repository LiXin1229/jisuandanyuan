# 缓冲 CE 解耦、数据共享与 compact 优化

基线为 `3d1dd44`，固定 epoch11 / 7×7 模型顶层 `cyclegan_bus_top`，Ti60F225 / C4，Efinity 2026.1.132，关闭全局 retiming。数字包括计算核心、主机总线、三块 cache、参数 ROM 和 Tanh。

最终整核 LUT4 **22883 → 21765，减少 1118（4.9%）**；缓冲层级 **10734 → 9913**。FF 5241、BRAM 147、DSP48 100、SRL8 134 均不变。没有增加寄存器级、指令拍数或切换时间。没有达到预估的缓冲 5k～6k / 整核 17k～18k。

## A/C：目标判断交给 CE，重复数据选择合并

直接采用优先 mux 的写法，保留相同 CE，先后选择三种旋转、行/列补边、tile 和零填充。独立 216408 像素检查通过，但缓冲变为 **11682 LUT**、整核 **24103 LUT**，因此撤回。

原因是分组名称不会减少真实数据输入：tile、补边列、补边行、左邻、右邻、上邻共有六种动态来源。`src_rot` 仍是三选一，`src_pad` 仍要选行/列，后面还要选装载/补边/旋转。CE 控制是否写入，不能替代同一个写入周期内的来源选择。原来的 AND-OR 项各自屏蔽未选来源，把所有数据掩码直接删除再 OR 会改变数值。A 与 C 涉及的是同一组选择逻辑，收益不能相加。

保留的优化将控制拆成两部分：

- CE 保留每个 cell 的 owner、目标行/列判断及复位禁止。
- 数据掩码只含全局相位、零填充状态和复位禁止，不再含目标 owner/行列。

同一网格行的 16 个 cell 实际只引用 10 个不同 tile 字节。例如列 0 和列 10 都引用 tile 的 x=7；装载哪个邻居由 CE 决定。去掉数据路径中的目标选择后，两者的 `tile OR column` 表达式相同，可以直接共用。

`mn_dw_buffer.sv` 明确只生成 **16×10=160 组**装载/列补边选择，再连到 256 个 cell。其余行补边/旋转选择和最后的 OR 保持一热形式。该部分从 2048 个逐位选择收敛为 1280 个，结构上少 768 个 LUT4；整体映射还会影响周围逻辑，所以最终以整核及缓冲报告为准。

加载、补边、旋转相位的互斥关系沿用原有执行器；cell CE、九次 tile 加载、蛇形旋转和补边顺序均未改变。零装载/零补边时所有数据来源被屏蔽，目标 cell 由 CE 写入零。

## B：变地址复制仍然需要读选择

把 12 项 AND-OR 改成 `cell_data[row*16+pad_src]` / `cell_data[pad_src*16+column]`，216408 像素检查通过，但缓冲为 **11250 LUT**、整核 **23362 LUT**，因此撤回。动态索引寄存器数组仍会综合成 mux；“复制第 s 行到第 d 行”的语义本身不能变成固定连线。

补边也不能仅限于固定外框。例如 `valid_w=1` 时，右侧三个目的列是网格列 4、5、6，它们处于网格内部。小图重复反射、部分 tile、零填充和两个补边轴都在现有接口与回归覆盖范围内。按完整 tile 的外框裁掉内部 cell 的补边输入会破坏这些用例。本轮保留 12 个有效源位置和全部目的位置的通用选择。

## D：当前 SDP 不存在第二个写入口

已核对随 Efinity 2026.1 安装的原语模型：

- `EFX_RAM10` 是一写一读，只有 `WDATA/WE/WADDR` 一组写入口；`RDATA` 为输出，读端口没有 host 写数据入口。
- `EFX_DPRAM10` 才有 `WDATAA/WEA` 和 `WDATAB/WEB`。合法端口宽度为 1、2、4、5、8、10，包含宽度检查，不能使用 20 bit TDP 配置。

bank0/1 用 80 个 1024×10 TDP，bank2 用 40 个 512×20 SDP。host/core 互斥能够用于仲裁，但不能增加 SDP 的写数据引脚。在当前 800 bit 一拍读写布局下，直接把 bank2 换成双写端口 TDP 需要 80 个 BRAM，整核 **147 → 187**，超出 180 目标。因此没有实施所述的“复用已有端口、只删 800 LUT”。改变位布局或拆成多拍读写需要重新设计数据路由和调度，不能视作原结构的无风险替换。

安装模型的哈希及宽度证据已归档到综合对照 JSON；原有 bank2 20 bit 切片 WE、主机空闲仲裁和写数据选择保持原样。

## E：高位归约已共享，进一步压缩共享树

基线网表已存在真实的跨模块共享。以 lane0 为例，`n32957` 是高 16 位全一判断、`n32963` 是高 16 位全零判断，各有五个 LUT 的逻辑锥。两者同时出现在量化逻辑和 Tanh 的 `LUT__59588` 输入端。因此上一轮所说“共用高位全零/全一判断”有硬件依据，不能再按两棵完整树重复计算收益。网表检查覆盖 100 个 lane，lane0 的消费者和基线网表哈希见对照 JSON。

`s[30:15]` 实际是 16 bit。16 输入 OR 在 LUT4 中需要四个分组加一个汇总，共五个 LUT；不能压成三个。

本轮新增只例化一次的 `mn_compact`，将表达式改写为：

```verilog
overflow = |(s[30:15] ^ {16{s[31]}});
compact = {overflow, s[31], s[15:0]};
```

每个 lane 用五个 LUT4 比较三位与符号位是否一致，一个 LUT4 汇总前四组，最后一个 LUT4 同时合并第五组和剩余一位的比较；共 **7 LUT/像素，100 路共 700 LUT**，没有 FF。真值表分别为 `7ffe`、`fffe`、`effe`。量化和 Tanh 接受同一份 18 bit 紧凑值，DSP 输出到后处理之间没有新增寄存器。

单独启用该改动，整核 **22883 → 22572**，减少 311 LUT。原语真值表经过全部高位/符号组合检查；量化、池化及 Tanh 的数值与拍数不变。

层级资源会随全局映射略有变化，不能把所有差值精确归到某个源码表达式。[综合对照 JSON](analysis/buffer_iteration6_trials.json) 保存各版资源、报告及暂存 RTL 哈希、原网表共享证据和 BRAM 原语证据。

100MHz 布局布线通过，setup slack **1.332ns**、hold slack **0.026ns**；基线为 1.343ns / 0.028ns，时序余量基本相当，没有实测的时序改善。未施加板级 IO 时序约束。

## 验证

- compact：134672 次检查，覆盖全部 131072 种高位/符号组合，并检查每个 lane 的每一位失配及两种符号扩展。
- 共享缓冲：216408 像素，五种核形状、蛇形旋转、全部补边源/目的位置和重复使用。
- 后处理：205800 像素，signed16 穷举、signed32 极值、激活和部分 tile 池化。
- 核心：201 组用例、252 条指令；8 组并行合计 21205 测试周期，全部逐指令执行拍数核对通过。
- 独立轨迹：3×3/7×7 的 9/49 次 MAC 连续发射，四条 PW 排队切换一拍；六条指令共 331 测试周期。
- 通用总线：数值、背压、3×3/7×7 中途复位、bank2 行掩码和非法地址隔离通过。
- 实际 epoch11 权重：RTL 与整核综合网表各六条指令，均为 860 测试周期，逐字节数值一致。
- FIFO RTL 和独立综合网表、模型 ROM/Tanh 资产及主机行写协议检查通过。

最终计数、逐指令时间、RTL/报告哈希见 [本轮结果](analysis/cyclegan_iteration6_results.json)。复现沿用 README 的仿真、综合、布局布线与模型检查命令，最后运行 `python tools/record_cyclegan_results.py`。

原有两帧整网整数指令模型结果继续保留，本轮没有重新运行整帧 RTL 或上板推理。
