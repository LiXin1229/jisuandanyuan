# 执行器效率优化：第二轮

> 本文为提交 `6a7c678` 对应的历史结果。当前已改为一拍全并行后处理，并增加完整 tile 的连续九拍 3×3 DW；最新资源和时间见 [第三轮效率记录](executor_efficiency_iteration3.md)。

基线为 `ace7b30`，目标为减少指令固定开销、保持整数参考逐值一致和 BRAM 不超过约 180。当前 RTL 的资源、时序和测试摘要保存在 [第二轮验证记录](analysis/cyclegan_iteration2_results.json)。DSP 移位/C 端口/ReLU 的独立核对见 [DSP48 可行性分析](dsp48_quantization_feasibility.md)。

## 为什么 PW 原来是 Cin+36 拍

这不是取指、译码或 BRAM 读取花了 36 拍。基线为节约逻辑，只有 4 个量化器，每拍处理一个 2×2 组；100 像素需要扫描 25 组。其余开销来自检查/清零、BRAM 到 DSP 之前多打一排 800 bit 数据寄存器、DSP A/B→P→W→O 流水、完成检测、单独写回状态和完成状态。输入通道已经能够连续每拍发射一个，主要问题在尾部处理和状态之间的空拍。

当前把量化器增加到 20 个、池化比较器增加到 15 个，每拍处理五个 2×2 组，合计五批，并在启动拍处理第一批；DSP 输出保持期间直接读结果，不复制 3200 bit 原始和。固定右移 8 位原本就是接线，换成 DSP 输出移位不会消除上述扫描时间。

另有三项直接减少固定开销：

- BRAM 第一次读请求与 DSP 清零重叠；请求返回后直接进入 DSP 的 A/B 寄存器，删除 800 bit 输入寄存器和参数暂存级。
- 量化/池化/Tanh 的有效结果直接写入 cache，删除单独 WRITE 状态。
- 保持错误检查在发射之前，保留舍入种子、raw continuation 和 DSP 流水有效标记的正确对齐。

## 时间口径和切换间隔

以下 E 是 FIFO 实际弹出指令的边沿到 `done` 拉高边沿之间的周期数。仿真 `commands.csv` 的 L 包含测试台下一拍采样完成，因此 **L=E+1**。当 FIFO 中已有下一条指令时，下一次弹出恰好在 `done` 后 1 拍；相邻弹出的间隔也为 L。

本轮四条排队 PW 单通道指令的实测边沿为：`pop16 → done29 → pop30 → done43 → pop44 → done57 → pop58 → done71`。因此 E=13，排队执行间隔 14 拍，完成到下一条弹出 1 拍。这个 1 拍没有被称为 BRAM 延迟，也不能把 E 和 L 混用。

PW 单通道、无舍入时，从 pop 记作第 0 拍：

| 相对边沿 | 动作 |
|---:|---|
| 0 | 弹出并锁存指令 |
| 1 | CHECK |
| 2 | CLEAR，同时发起首次 cache/参数读 |
| 3 | 读回数据进入 DSP A/B |
| 4 | P |
| 5 | W |
| 6 | O |
| 7 | 后处理第一批 |
| 8～11 | 后处理其余四批 |
| 12 | 写回 cache |
| 13 | done |
| 14 | 可弹出下一条排队指令 |

## 各指令实测与公式

普通输出、无舍入的 E 如下；K 为核面积，Cin 为 PW 指令内输入通道数。

| 指令/条件 | 基线 E | 当前 E | 当前排队间隔 L |
|---|---:|---:|---:|
| PW | Cin+36 | Cin+12 | Cin+13 |
| PW Cin=1 | 37 | 13 | 14 |
| PW Cin=32 | 68 | 44 | 45 |
| NORM | 38 | 14 | 15 |
| ADD | 38 | 14 | 15 |
| DW 1×2 / 2×1 | 338 | 205 | 206 |
| DW 2×2 | 364 | 229 | 230 |
| DW 3×3 | 429 | 289 | 290 |
| DW 7×7 | 949 | 769 | 770 |
| CONV 1×1，保留 raw 和、不输出 | 10 | 8 | 9 |
| CONV K>1，保留 raw 和、不输出 | 285+13K | 176+12K | 177+12K |
| CONV 7×7，最后一段输出 Tanh | 978 | 819 | 820 |
| NOP/检查阶段拒绝的指令 | 2 | 2 | 3 |

基线 raw 公式等价于 `285+13K`，例如 K=2 为 311、K=49 为 922。CONV 普通最终量化段与同核 DW 相同；1×1 最终段与 PW Cin=1 相同。PW 的 raw 中间段为 `Cin+7`。首次不保留累加器、且启用 rounding 时，PW/ADD/空间 CONV/DW 额外 1 拍，用于在 DSP 中预置 +128；后续 keep 段不重复加。NORM 把舍入并入 bias 项，不增加拍数。

测试台末层 8 输入通道 7×7/Tanh 的八条连续累加指令，L 实测为 `765,765,765,765,765,765,765,820`；不含主机装载时，首条 pop 到最后 done 共 6174 拍（100MHz 下 61.74μs），基线为 7439 拍。该值是一块输出 tile 的核内时间，不能作为整网 FPS。

PW 指令内仍是每拍一个输入通道的 MAC。以排队发射间隔计算，Cin=32 时有效 MAC 拍占比从 `32/69=46.4%` 提高到 `32/45=71.1%`。短 PW 仍受启动和输出开销影响。

## DW 为什么也变快

10 个 halo BRAM 保持不变，利用原生不对称 16 bit 写、8 bit 读和字节写使能，一拍装入相邻两个像素。考虑 cache 的 5×5 象限布局，中心行按单像素、四对像素、单像素装入，跨象限时不错误拼接。整个 16×16 halo 从 256 个装载拍降至 160 拍；不增加第二套像素地址译码，复用相邻 16 bit 数据选择。

中心 tap 已从原 tile 累加，窗口生成器跳过其 10 行构建。其余窗口写入共享 cache 后，延迟一拍发起读取并送 MAC，同时构造下一个窗口；消除全部窗口生成后再单独扫描计算的阶段。同址 SDP 读写不在同一拍发生。

目前每个非中心窗口仍需约 12 拍生成，DW 的主要剩余开销是 halo 装载和窗口构造。后续若进一步压缩它，需要重新权衡多路 cache 读、逐行数据选路和窗口寄存器成本，不能只按 DSP 峰值吞吐估算。

## 验证

- 核心 RTL：109 组用例、160 条指令、33092 个测试周期；基线相同用例为 44017 周期。包括极值、舍入、饱和、池化、边界、ring、raw continuation、7×7/Tanh、排队和非法指令隔离。
- 后处理：205800 像素，signed16 全穷举、signed32 极值、部分 tile 池化及处理中复位。
- 总线：PW/DW golden、staging、背压、复位、第三 bank 行掩码和非法地址隔离。
- epoch11 实际权重：ROM/Tanh 资产检查，以及五条模型总线指令，原始 RTL 与综合网表均通过，各 918 周期。
- DSP 原语数值探针：C 端口冲突、预装载移位量、四种 OP、不自动 int8 饱和、W 原始累加与 O 移位输出。
