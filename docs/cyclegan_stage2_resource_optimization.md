# 第二阶段资源优化

接续 `c31d0db`，保持 epoch11 权重、固定归一化、计算单元算术及三层编码加九块残差的数值结果。按本轮确认，以已实现的 FF 降幅收敛，保留全部逐块回读、实际输入 CRC 和连续运行验收能力。

## 第一阶段之后为什么增加资源

算法继续使用同一个计算单元，但此前实现增加了独立残差指令生产者、块间控制、累计计数和四个 32 位 VIO 探针。官方调试核对输入逐位同步并配置扫描寄存器；层级报告估算，仅调试链就增加约 414 FF，约占两阶段 FF 增量的三分之二。

阶段一还通过 `ENCODER_ONLY` 裁剪了 ADD 等路径；阶段二需要残差相加，指令 FIFO 中变化的字段也更多。因此两份板级网表不能直接当作“完全相同硬件，只替换指令内容”比较。额外 13 BRAM 全部来自参数 ROM 从 1067 词扩大到 14027 词，feature cache 和 DSP 没有增加。

## 本轮修改

- VIO 保留状态和完整 800 位数据回读，将 13 个独立统计输入改为通过现有命令 4 按索引读低 32 位。输入探针由 1248 位减少到 832 位，统计能力保留。
- 去掉板壳重复的 800 位 `read_data` 寄存器。`read_hold` 在下一次回读命令之前保持；完成 toggle 经两级同步后才应答，VIO 仍保留原有输入同步器，主机在应答后读取结果。
- 统计读取只更新 `read_hold[31:0]`，上部 768 位保持。主机只解释低 32 位，避免为无效的高位增加清零选择逻辑。cache 和 DDR 回读仍返回完整原有数据。
- 两个调度器用 3 位未完成计数替代累计发出/完成比较。最大为四条 FIFO 指令加一条执行指令；同拍发出和完成时保持不变，排空条件和交接周期保持一致。编码器额外保留 6 位完成索引，用于首个输出的时间戳。
- 三个邻域地址共享列地址加法和三槽 ring 译码，避免重复的宽取模及可变行间距乘法。
- 固定残差周期计数用 19 位、块周期用 16 位，对外零扩展为 32 位。固定九块无外部 DMA/运行期主机访问，每块 49155 拍、九块 442395 拍；仿真检查计数范围。今后扩大该调度规模时需重新计算位宽。通用计算单元保持原样。

## 资源和时序

| 完整 DDR/JTAG 板级网表 | 优化前 | 本轮 | 减少 |
|---|---:|---:|---:|
| LUT4 | 18078 | 18057 | 21 |
| FF | 12592 | 10581 | **2011（15.97%）** |
| DSP48 | 100 | 100 | 0 |
| BRAM | 211 | 211 | 0 |
| 150 MHz setup / hold | 0.955 / 0.026 ns | 1.115 / 0.029 ns | — |

本轮 FF 也低于第一阶段的 11967。全部已分析的布线后时钟关系余量非负。LUT 降幅很小，本轮主要收益是减少调试链、重复数据寄存器及控制计数的 FF。

已拒绝两个统计回读候选：416 位宽统计选择器为 18386 LUT / 11457 FF；按字读取但清零整个回复为 18463 LUT / 10657 FF。只保留低 32 位更新后，再通过计数和地址精简得到本轮版本。没有为减少 FF 而接受 LUT 增长，也没有改动量化、舍入或 feature 布局。

## 验证与协议

原生正常、反色和增加 DDR 延迟的连续运行三组回归全部通过，最终统计与基线逐项相同。同一位流两次下载后的六帧正式验收通过：四帧逐块回读、两帧连续运行，共 **1459200 个值零差异**，各块 SHA256 与优化前一致，六帧实际输入 CRC 全部正确，指令供应等待均为零。九块残差仍为 442395 拍，完整前缀实测 1298350～1299187 拍。150 MHz 布线后的全部已分析时钟关系 setup/hold 均通过。

机器记录见 [cyclegan_stage2_resource_optimization.json](analysis/cyclegan_stage2_resource_optimization.json)。未修改的计算单元和 DDR 读桥使用源码哈希匹配的历史回归证据；本轮重新运行全部三组整帧 RTL 仿真和上板验收。

板级签名和调试 UUID 前缀为 `0xe313`；驱动也兼容旧 `0xe312`。

命令 4 的 bit27 为 0 时仍为 cache tile 回读；为 1 时，低四位选择统计字 0～12，返回值仅低 32 位有效。顺序为总周期、计算单元忙周期、首输出时间、帧数/输入块数、帧 ID、DDR 相位状态、指令等待、数据等待、输入 CRC、残差状态、编码周期、残差周期、最近块周期。统计只允许在空闲或逐块暂停时读取，因此多字回读属于同一个静止点。`Board.read()` 返回实时状态、数据及缓存的统计；`Board.snapshot()` 执行统计回读。

验收检查正常和反色输入的全部编码池化值、九块 ADD 写回及暂停回读，并增加 ring 地址等价、未完成计数范围和残差周期范围检查。保留增加 DDR 延迟的连续运行回归，与历史版本逐项比较最终统计。

上板验收使用相同位流的两次下载：第一组两帧完整输入 DDR 和九块输出回读；第二组两帧逐块回读及两帧连续运行。每帧校验实际装载 CRC、全部回读值、块周期、帧序和零指令等待。机器证据保存实际编译副本、源码、位流、报告及回读 SHA256，并和历史各块哈希比较。

新位流的相位 5 单帧对照通过，说明旧位流的相位 5 失败不能作为所有布局布线版本必须复现的前提。默认相位仍为 6；正式验收仍由每帧 CRC 和数值比较决定，旧位流的失败对照保留在历史证据中。

## 复现

```powershell
./scripts/run_residual_modelsim.ps1 -OutputDir build/stage2_optimized
./scripts/run_residual_modelsim.ps1 -Inverted -OutputDir build/stage2_optimized
./scripts/run_residual_modelsim.ps1 -DdrDelay 45 -Continuous -OutputDir build/stage2_optimized
./scripts/run_residual_board.ps1 -OutputDir build/stage2_optimized -ResourceBaselineJson docs/analysis/cyclegan_stage2_deployment.json -Program -RepeatBoot -PhaseControl
python tools/record_residual_deployment.py --out build/stage2_optimized --optimization
```

本轮产物隔离在 `build/stage2_optimized`，历史第二阶段证据保持不变。资源基线检查在上板前要求 LUT、FF 均下降；`-PhaseControl` 记录相位 5 通过或预期 CRC 失败两种观测，再进行相位 6 的完整验收。
