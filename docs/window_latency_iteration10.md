# 保留八 bank BRAM 的装载与初始化折中优化

基线 `1561ed4`，固定 epoch11 / 7×7 模型，Ti60F225 / C4，Efinity 2026.1.132，150 MHz，关闭 retiming。目标是在约 200 BRAM 内，用少量新增逻辑缩短空间卷积等待。

| 窗口 LUT4 | 4649 | 5760 | +1111 |

保留 256 byte 静态 BRAM 和 100 byte 工作窗口，没有增加完整寄存器网格或第二份工作窗口。9 次邻居 tile cache 读取、cache 容量与主机写入协议保持原样。

| 无填充、正常输出 | 上一版 E | 本轮 E | 150 MHz 本轮时间 | 执行时间减少 |
|---|---:|---:|---:|---:|
| 1×2 / 2×1 | 70 | 45 | 300 ns | 35.7% |
| 2×2 | 72 | 47 | 313 ns | 34.7% |
| 3×3 DW | 77 | **52** | **347 ns** | **32.5%** |
| 7×7 DW | 117 | **92** | **613 ns** | **21.4%** |
| 首次 MAC，弹出后 | 63 | **38** | 253 ns | 39.7% |

E 是 FIFO 弹出沿到 done 沿，不含传输及排队等待。3×3 / 7×7 的 9 / 49 次 MAC 仍连续，末次 MAC 到 done 仍为 6 拍。排队切换仍一拍。

空间核公式变为 `E = 核面积 + 43 + 9×需要修补的边数`，raw 减 1，Tanh 加 54。因此 3×3 为 52～88 拍，7×7 为 92～128 拍；最终 7×7 CONV/Tanh 为 146～182 拍。PW、NORM、ADD 的执行时间不变。

## 先减少浪费的写入，再重叠初始化

### 左右 halo 按列写：48 → 34 次行/列写入

原来所有 tile 都按行写。左右中间 halo 各为 10×3 区域，也各写了 10 次；每次只使用 3 个像素。

八 bank 的原有端口结构已经支持整列读写，因此：

- 中心 10×10：10 次行写入。
- 上、下 3×10：各 3 次行写入。
- 左、右 10×3：各 3 次列写入。
- 四角 3×3：各 3 次行写入。

合计 `10 + 4×3 + 4×3 = 34`，省 14 拍。增加的是 tile 的行/列选择和少量控制，不增加 BRAM。下一 tile 仍在当前最后一次写入沿发出 cache 读取请求，随后直接开始下一 tile。

### 同一次写入同步填充工作窗口：再省 11 拍

写入 BRAM 前已经存在一条按自然顺序排列的 128 bit 行/列数据。将其中对应核起点的 10 个字节，也写进现有 100 像素工作窗口：

- 写行时，只更新匹配该行、且属于当前 owner 的工作窗口位置。
- 写列时，只更新匹配该列、且属于当前 owner 的位置。
- 补边写入时，同步更新工作窗口中受影响的行或列，包括零填充与部分 tile。

数据来自已计算的共享行/列通路，目标位置交给 CE 判断；没有为 100 个像素分别增加完整 tile 选择器。

加载及补边完成后，工作窗口已经正确。核心在完成沿直接发出 tap0 和首个边界预取，省去十行初始化读取及其排空等待。首个预取用本条指令的起点，而非上一条卷积留下的 x/y；否则连续指令切换会读错边界。

`mn_dw_buffer_bram` 的 `OVERLAP_INIT=1` 是生产配置，要求 `init_x/y` 在加载、补边期间保持稳定，核心由当前 cmd 提供。默认 `OVERLAP_INIT=0` 保留独立读取任意初始视图的接口，用于原有专项测试。

## 为什么没有采用完整寄存器窗口

完整寄存器方案只作为速度和资源成本的对照：无填充 3×3 / 7×7 可到 30 / 66 拍，但整核需要 19993 LUT、5239 FF、187 BRAM。相对基线增加 5310 LUT；本轮保留方案只增加 1124 LUT，约为其逻辑增量的 21%。

完整寄存器试验通过六条执行轨迹、epoch11 RTL 抽查及 150 MHz 布局布线，未完成完整 RTL 和综合网表回归，不作为交付实现。生产源码已经恢复 BRAM 结构。

## 时序与复现

SDC 周期 `6.666667 ns`，报告显示 6.667 ns / 149.993 MHz。最终 setup / hold 为 0.725 / 0.026 ns，本次布线的分析 Fmax 为 168.294 MHz。关键路径为 `cache/plane[125].ram → window_pixels[523]`，9 级逻辑。板级 I/O 未约束，未板测。

可写参数顶层 `mobilenet_bus_top` 也独立完成 150 MHz 布局布线：15585 LUT、4014 FF、178 BRAM、100 DSP，setup / hold 为 0.802 / 0.027 ns，分析 Fmax 为 170.503 MHz。这里参数走可写 RAM，资源数不能替代固定模型顶层的 195 BRAM 统计。

## 功能验证

- 完整计算单元：201 个用例、252 条指令、26099 个测试平台周期；逐条执行时间模型通过，覆盖填充、部分 tile、raw 累加、Tanh 及预期非法指令。
- 生产窗口：251800 个像素检查，在 `init_start` 前比较装载结果，覆盖五种空间核、起点 0/2/3、首拍同时预取、全部修补行列、零 tile 和中途复位。原 BRAM 任意初始视图测试另有 327100 项检查通过。
- epoch11 固定模型：RTL 与综合网表均通过六条真实权重指令，均为 956 个测试平台周期；覆盖 DW/PW、固定 BN、7×7 CONV/Tanh、ADD 和第三 cache bank。
- FIFO RTL 与综合网表通过满空、同时读写及重复复位；cache、后处理、compact、PE 输入选择专项通过。cache 网表专项沿用未改动实现的结果，并核对源码、测试台及网表哈希。
- 总线测试通过 PW/DW 对照、写入暂存、背压、3×3/7×7 计算中复位、第三 bank 行掩码和非法地址隔离；六条执行轨迹核对首次 MAC、连续 tap、六拍尾部与一拍队列切换。
