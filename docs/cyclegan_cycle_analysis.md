# 当前实时 CycleGAN 指令连续性与整帧周期分析

分析对象为 `9d7c606` 对应的 320×240 网络和 171.428571 MHz 计算时钟，每拍 5.833333 ns；使用同一套 100 像素 PE。依据当前 RTL、已有 390 条真实 DSP/BRAM 指令周期记录，以及 2026-10-10 最近一次上板验收。此次分析没有重新进行上板测试。

数据、缓存槽和读写端口就绪时，当前调度可以连续供应指令。计算单元内部仍按装窗、乘加、流水线排空、后处理和指令切换分段工作，因此“指令饥饿为 0”与“每拍都有有效乘加”是不同指标。

## 指令供应与实际空隙

- `mn_instruction_fifo.sv` 有四个 128 bit 指令槽，调度器可以在当前指令执行期间提前填充。权重在片上模型 ROM，不需要逐条从 DDR 获取指令或权重。
- 编码器在所需行已装载后持续置 `instruction_valid`；残差模块的数据全部驻留缓存，RUN 状态持续发指令；解码器在行数据就绪、目标输出槽可用时持续发指令。
- 最近两种显示模式的上板完整帧样本、两组整网原生算术仿真，`command_wait_cycles` 都为 0。该计数只统计具备执行条件后、计算核空闲且指令 FIFO 为空的等待；不包含首次填充、行/层排空、数据依赖和输出槽等待，不能据此宣布全部空隙已消除。
- `mobilenet_unit.sv` 的 `COMPLETE` 状态返回 `IDLE`，下一沿才能 `fifo_pop`。即使 FIFO 非空，连续指令之间也固定有一拍空闲。解码打包的 `host_cache_rd` 还可能延后 FIFO 弹出，这是端口竞争，不是缺少指令。
- DW 装窗结束后的 9/49 个 tap 连续送入 PE；PW 的各输入通道乘加同样连续。两条指令之间，装窗、补边、等待流水线和量化/Tanh 期间没有持续的 PE 有效输入。
- 整帧输入和中间特征采用行缓存与 DDR 流式交换。某一批数据装载完成后可连续执行，后续行和后续层仍需要装载，不能把“输入图像已经在 DDR”视为“整网所有操作数已在片上”。

`cyclegan_encoder.sv` 中的 `mac_cycles` / 板上 `prefix_mac_cycles` 实际累加 `core_busy`，含装窗和后处理，不能直接作为 DSP 有效乘加拍数。

## 各类指令耗时

以下 E 是 FIFO 弹出沿至 done 沿的周期数，对应现有 `sim/check_executor_cycles.py`。整帧统计还需每条指令增加一拍切换。所有生产指令处理完整 10×10 tile；C 是 PW 输入通道数，B 是需要反射修补的边数，当前图像普通边界 B=1、角点 B=2。

| 指令 | 当前生产流程的 E | 说明 |
| --- | ---: | --- |
| PW | C+9 | 含首次舍入；C=3/8/16/32 时为 12/17/25/41 拍 |
| DW 3×3 | 52+9B | 编码器首层反射补边；其余 DW 为零填充，B=0 |
| 固定 NORM | 10 | 包含激活/池化选项时仍为 10 拍 |
| 残差 ADD | 10 | 当前关闭 ADD 首次舍入；开启时为 11 拍 |
| 转置相 CONV 1×1 | 首通道 9，中间 8，末通道 9 | 使用原始累加保留；当前每相 C≥8 |
| 转置相 CONV 1×2 / 2×1 | 中间结果 23，末通道 24 | 已采用精简前向邻域装载 |
| 转置相 CONV 2×2 | 中间结果 31，末通道 32 | 已采用精简前向邻域装载 |
| 输出 CONV 7×7 | 前七通道 91+9B，末通道 146+9B | 末通道包含额外 54 拍 Tanh |

空间核的通用公式为 `E = 核面积 + 装载及固定开销 + 9B - raw + Tanh开销`。完整前向 1×2/2×1 的装载及固定开销为 22 拍，2×2 为 28 拍，3×3/7×7 为 43 拍。`raw=1` 表示保留累加、不进行最终量化，少一拍；仅最终 Tanh 结果增加 54 拍。空间核的首次舍入与装窗重叠，不再额外增加 E。PW/1×1 的通用公式为 `E=C+8+rounding-raw`。

例如内部 DW 3×3 虽有 9 拍连续 tap，单条指令仍需要 52 拍执行加 1 拍切换，约 309.17 ns。32 通道 PW 为 41 拍执行加 1 拍切换，约 245 ns。

## 完整一帧的理论执行下界

按照 RTL 实际循环枚举全部 170880 条指令，并计入边界反射、原始累加、归一化、残差加法和最终 Tanh。下表忽略 DDR 延迟、打包端口竞争、输出槽背压及行/层排空，只保留当前计算单元执行周期与每条指令一拍切换。因此它是理论下界，不是对现有整板能达到该帧率的承诺。

| 用户划分的阶段 | 指令条数 | 核忙碌周期 ΣE | 加指令切换的周期 | 理论时间 |
| --- | ---: | ---: | ---: | ---: |
| 输入至残差前：三个编码器 | 28416 | 537552 | 565968 | 3.30148 ms |
| 九个残差块 | 17280 | 425088 | 442368 | 2.58048 ms |
| 三个转置卷积 | 106752 | 2184000 | 2290752 | 13.36272 ms |
| 输出 7×7 + Tanh | 18432 | 1828224 | 1846656 | 10.77216 ms |
| 合计 | **170880** | **4974864** | **5145744** | **30.01684 ms** |

`T = (ΣE + 指令数) / 171428571.428571 = 30.01684 ms`，对应约 **33.31463 FPS** 的理想执行上限。仅 ΣE 是 29.02004 ms；少算切换会低估整帧 0.9968 ms。若以第一条 FIFO 弹出至最后 done 为区间，边界可少计一拍；这里按连续帧摊销口径每条增加一拍。

| 细分层 | 指令数 | 执行加切换周期 | 时间 |
| --- | ---: | ---: | ---: |
| 编码器 1：320×240，3→8 | 14592 | 272592 | 1.59012 ms |
| 编码器 2：160×120，8→16 | 9216 | 187392 | 1.09312 ms |
| 编码器 3：80×60，16→32 | 4608 | 105984 | 0.61824 ms |
| 残差九块：40×30，32 通道 | 17280 | 442368 | 2.58048 ms |
| 转置 1：40×30→80×60，32→16 | 25344 | 556224 | 3.24464 ms |
| 转置 2：80×60→160×120，16→8 | 26112 | 565632 | 3.29952 ms |
| 转置 3：160×120→320×240，8→8 | 55296 | 1168896 | 6.81856 ms |
| 输出：320×240，8→3 | 18432 | 1846656 | 10.77216 ms |

关键汇总可直接复算：

- 编码器每 tile 指令数依次为 `3+8+8=19`、`8+8+16+16=48`、`16+16+32+32=96`，tile 数分别为 768、192、48。首层反射补边额外增加 `3×(2×32+2×24)×9=3024` 拍。
- 每个残差块有 `12×32×5=1920` 条指令。每通道的五条指令共 `52+10+41+10+10=123` 拍执行，连切换为 128 拍；每块下界 49152 拍。加每块三拍调度填充/排空，得到实际 49155 拍，九块 **442395 拍**，与板端相符。
- 转置卷积每个输出通道 tile 的四相计算加四条 NORM，共有 `4(C+1)` 条指令。四相执行周期依次为 `8C+2`、`23C+1`、`23C+1`、`31C+1`，再加 40 拍 NORM，合计 `85C+45`。三个阶段的输出通道 tile 数为 192、384、1536。
- 输出每个 RGB 通道 tile 有八条 7×7 CONV，执行 `7×91+146+8×9B=783+72B` 拍。共有 2304 个通道 tile，总边数为 `3×(2×32+2×24)=336`，因此输出忙碌周期为 `2304×783+336×72=1828224`。

## 与最近上板数据对照

下面使用既有验收记录中的完整帧 `processing_sample` 与 60 秒吞吐统计，二者不是同一统计口径。单帧样本是网络启动到完成的处理时间；持续帧率还受帧切换、摄像头和显示同步影响。两种显示模式都运行完整网络，差异来自视频访存竞争。

| 显示模式 | 样本处理周期 | 样本处理时间 | 超过理论下界 | 60 秒实测 FPS |
| --- | ---: | ---: | ---: | ---: |
| 网络结果 | 6127039 | 35.74106 ms | 5.72422 ms | 27.55983 |
| 配对原图 | 5855367 | 34.15631 ms | 4.13947 ms | 28.78335 |

两帧样本的核忙碌周期都为 **4974864**，与逐条汇总完全一致，核忙碌占比约 81.20% / 84.96%。指令等待均为 0。数据等待计数为 819187 / 514434，但这些是调度生产端等待所需行的周期，可能与 FIFO 中已有指令执行重叠，不能直接加到执行时间或等同于 PE 空闲。

按 `issue_valid` 的 RTL 行为另行推算，整帧 PE 输入有效共 **1469568 拍**，其中包含舍入常数、固定归一化和残差加法。折算为 8.57248 ms 的有效输入拍，约占两帧实际处理时间的 23.98% / 25.10%。这是静态推导，不是新增板端计数；它说明计算核 busy 时，大量周期仍花在窗口装载及结果处理，不能把 busy 占比当作 DSP 乘加利用率。

后续优化应优先观察转置卷积的重复装窗、7×7 输出的通道间装窗/累加开销，以及 DDR 预取、打包读端口和输出槽释放。转置与最终输出占理论执行时间 **80.40%**。扩大指令 FIFO 对当前已就绪区间的帮助有限；固定一拍切换本身只占该执行下界 3.32%。如果只减少外部等待而不改变现有指令内部执行过程，33.31 FPS 是乐观上界，实际仍受不可完全重叠的端口和协议开销限制。
