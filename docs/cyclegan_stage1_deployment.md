# CycleGAN 四阶段迭代：第一阶段

基线：`48c80e9`。目标器件 Ti60F225 C4，Efinity 2026.1.132，计算时钟 150 MHz，DDR 用户时钟 96 MHz。参数来源为 epoch11，固定 BN；参考工程保持只读。

本文记录第一阶段提交 `397a3cd` 的仿真、上板数值和资源/时序验收结果。后续九个残差块的独立实现及验收见 [第二阶段部署记录](cyclegan_stage2_deployment.md)，不以本阶段历史证据替代后续结果。

## 阶段约定

| 阶段 | 输出及范围 | 验收要求 |
|---|---|---|
| 1 | RGB 输入至残差前：32×30×40 | 整帧仿真、上板两帧逐值回读、资源与时序、独立 Git 提交 |
| 2 | 九个残差块：32×30×40 | 逐块验证及板上回读、资源与时序、独立 Git 提交 |
| 3 | 三层真实转置卷积：8×240×320 | 四相重排、边界及 DDR 背压验证、上板、资源与时序、独立 Git 提交 |
| 4 | 7×7 输出卷积与 Tanh：3×240×320 | 整网图像逐字节回读、上板、资源与时序、独立 Git 提交 |

每阶段复用同一计算单元。用计数器区分指令供应等待、数据等待和执行器忙时间，优先减少可以通过预取隐藏的等待；不为降低等待重复配置计算阵列或整层缓存。

## 第一阶段实现

`rtl/cyclegan_encoder.sv` 是片上调度器。它按行交错推进三层编码，直接生成 128 位指令并提前填满现有四深 FIFO；当前空间 tile 的指令无需主机逐条下发。每行的全部指令完成后，才向下一阶段发布该行。

`rtl/cyclegan_rgb_loader.sv` 由参考工程的小行装载器派生，每次只保留十个像素，并把 DDR 响应保持到三通道写完。数据布局改为同一空间位置的通道连续，供当前 PW 直接读取。

共享计算单元增加默认关闭的 `STREAM_WRITES` 参数：拥有完整行槽生命周期的调度器可写入已释放的 raw 槽。`host_stream_ready` 只在核心 cache 端口不读写时授权提交，装载器在其余拍保持当前通道和像素；DDR 请求及 PE 运算仍可重叠，核心指令不等待装载器提交。普通总线顶层默认仍遵守空闲访问协议。该模式不允许无所有权管理的主机任意并发写入。

`ENCODER_ONLY` 配置使用精确的 1067 词参数 ROM，映射三块 512×16 RAM；指令范围限制到编码算子和参数。后续层参数、Tanh 及通用总线暂存器均不计入本阶段板级网表，因为它们没有实例化到有效路径或被常量消除。

### cache 固定分区

| 地址 | 用途 | 排列 |
|---|---|---|
| 0～287 | 三行 RGB 输入 | 行槽 → tile x → 三个通道 |
| 288～671 | 编码 1 三行 ring | 行槽 → tile x → 八个通道 |
| 672～1055 | 编码 2 三行 ring | 行槽 → tile x → 十六个通道 |
| 1056～1439 | 编码 3 完整结果 | 通道 → tile y → tile x |
| 1440～1455 | DW 中间结果 | 连续输入通道 |
| 1456 | PW 临时结果 | BN 原地读取，再池化写入输出象限 |

没有分配第二套 feature cache，编码中间特征不写 DDR。MaxPool 直接通过当前计算单元的象限写回，将相邻四个 5×5 结果合成为一个 10×10 tile。

### 预取策略及被拒绝的按列候选

初版仅在一整行消费完毕后装载下一行，能够实现指令无饥饿，但真实 DDR 下仍产生约 26.4 万拍等待。

实验候选记录实际完成的 DW tile 进度。处理 raw 行 y 时，上 halo 行 y−1 的列 c，最后由 tile c+1 读取；该 tile 的第三个 DW 通道完成后，列 c 才交给装载器复用，写入行 y+2。右边界完成后释放最后两列。第一行没有上 halo，第三个行槽可立即用于预取。

预取行必须整行写完才更新 `loaded`，下一行计算不会读取半写入的行。原生 RTL 测试额外检查 DMA 写地址与核心读取/写回地址没有碰撞。

不带 cache 回压的按列候选通过原生仿真，但两次上板分别出现 89、311 个输出差异；加入回压后首帧通过，第二帧仍出现 123 个差异，整帧 DDR 输入回读均正确。回压未解决全部问题，不把未经证明的物理碰撞机理写成定论。失败证据保存在 `build/stage1/board_failed*_result.json`。

退回整行释放、暂停 JTAG 轮询仍能出现差异。增加实际装载流 CRC32 后，出错反色帧的输入 CRC 已经错误，证明问题早于 PE 算术。最终采用本工程 `cyclegan_ddr_read_bridge.sv`：在完成 toggle 同步后，再等待三个计算时钟才发布稳定响应，继续复用原数据寄存器。保留 CRC 以验证后续每一版位流的真实输入。

最终位流在两次重新下载后连续通过六帧，尚未通过独立实验区分响应稳定期、布局变化及 DDR PHY 校准变化各自的贡献，因此不宣称已证明所有早期差异的物理根因。每个后续阶段必须重新做输入 CRC 和输出数值验收。

当前 `COLUMN_PREFETCH=0`，禁用该实验候选，整行消费完后才释放上 halo 行。连续供指令、三层交错和对安全行槽的后台装载仍保留；只限制复用旧行的时机。常量关闭的按列计数及逻辑不占最终硬件资源。后续若重新启用，需要重新通过板级数值验证。

地址中的乘 3/8/16 改为常量移位和加法，省去地址算术的两个 DSP。指令生成器没有独立指令 ROM，也没有增加数据缓存 BRAM。

## 验证和证据

最终结果由 `docs/analysis/cyclegan_stage1_deployment.json` 记录，包含当前源码、位流、综合/时序报告和两帧上板结果的 SHA256。只在全部验收通过后记录阶段完成并提交。

| 项目 | 最终实测 |
|---|---|
| 输出 | 32×30×40，384 tile / 帧 |
| 上板验证 | 两次下载，普通/反色交替共六帧；230400 个特征值零差异 |
| 输入完整性 | 六帧实际装载 CRC32 全部匹配；首次两帧另回读全部 DDR 输入字节 |
| 板内单帧时间 | 5.707～5.714 ms，约 85.6 万拍；含 RGB 装载，排除 JTAG 上传及回读 |
| 指令供应等待 | 每帧 0 拍；每帧 28416 条计算指令 |
| 数据等待 | 约 29.0 万拍，仍有优化空间 |
| 资源（包含 DDR、JTAG、调度器） | 17304 LUT4、11967 FF、100 DSP48、0 DSP24 |
| BRAM | 30 RAM10＋168 DPRAM10＝198 / 256 |
| XLR | 26030 / 60800，42.81% |
| 150 MHz 布线时序 | setup +0.937 ns，hold +0.035 ns；全部已分析时钟关系非负 |
| 原生整帧仿真 | 两种输入及 45 拍基础 DDR 延迟均通过；每帧检查 268800 个池化值 |
| 异步读桥仿真 | 2000 次请求，3/4 拍突发、随机返回延迟、响应背压、响应保持 |
| 计算单元兼容回归 | 201 用例 / 252 指令及总线测试通过 |

测试使用真实厂商 DSP/BRAM 模型，未采用行为 PE 或行为 cache 替代整帧验证。ModelSim 的优化网表日志中 `(fast)` 是仿真器内部优化后的单元名称，不表示替换了原生算术模型。

每帧检查三层编码的 268800 个池化输出值、最终 384 个 cache tile、28416 条计算指令、23040 次输入行提交，并要求指令供应等待计数为零。DDR 请求和响应有确定性随机等待，最终地址回读也逐 tile 比较。

板级壳复用参考工程的 DDR 控制器、输入帧双缓冲和官方 JTAG/VIO 接口，读桥由其派生并增加响应稳定期，算术路径全部使用本工程计算单元。校验签名为 `0xe311`；JTAG 上传 320×240 RGBX 后由 FPGA 自主计算，完成后回读全部 38400 个最终特征值。上传和回读耗时不计入板内推理周期。

本阶段不接摄像头或 HDMI，暂不测量视频端到端帧率。

## 复现

```powershell
# 原生整帧 RTL，推荐 ModelSim；两种输入分别执行。
./scripts/run_encoder_bridge_sim.ps1
./scripts/run_encoder_modelsim.ps1
./scripts/run_encoder_modelsim.ps1 -Inverted
./scripts/run_encoder_modelsim.ps1 -DdrDelay 45

# Icarus 使用同一原生模型，仿真较慢。
./scripts/run_encoder_sim.ps1

# 完整板级构建、时序检查、JTAG 下载及两帧回读。
./scripts/run_encoder_board.ps1 -Program -RepeatBoot

# 在两帧原生仿真及板上验证完成后汇总机器证据。
python tools/record_encoder_deployment.py
```

构建脚本把源码复制到 TEMP 下的 ASCII 路径，避免 Efinity 的中文路径限制；报告、位流和回读证据保存在本工程 `build/stage1`，不修改参考工程。复现仍依赖本机参考工程提供的 DDR/板级源文件和已导出的 epoch11 模型资产。

## 后续阶段的接续

阶段 2 直接消费 1056～1439 的编码结果。优先让 384 tile 的残差输入与输出分别驻留两个区域，DW 中间结果按通道连续保存，PW/BN 后通过 ADD 读取对应 skip。只有 ADD 完成后才能释放输入；块末尾交换输入/输出区域。

具体接续分配：第一个块从 1056～1439 读、向 0～383 写；之后在 0～383 和 384～767 之间交换。保持通道优先布局 `base + channel*12 + tile_y*4 + tile_x`，因此 DW 使用 `tile_pitch=1,row_pitch=4`，不需要重排整份输入。1440～1471 保存 32 通道 DW 结果，1472 是 PW/BN 临时值。每个空间 tile 连续提交 32 组 DW/BN、32 组 PW/BN/ADD，九块共 17280 条指令。此为阶段 2 的实现准备，尚未通过板级验证。

阶段 3 加入四相交错模块，并沿用行槽所有权和执行完成计数；阶段 4 接入已有 7×7 CONV 续算及 Tanh。二至四阶段的资源数、板上结果和 Git 提交需分别产生，不能以本阶段验证替代。
