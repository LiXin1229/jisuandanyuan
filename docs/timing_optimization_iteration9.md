# 150 MHz 时序收敛与参数 ROM 优化

基线 `857e566`，Ti60F225 / C4，Efinity 2026.1.132，固定模型顶层 `cyclegan_bus_top`。按用户最终要求，以 **150 MHz** 为目标，保持指令执行拍数，BRAM 预算约 200。

## 最终结果

| 项目 | 上一版，100 MHz 约束 | 本轮，150 MHz 约束 |
|---|---:|---:|
| LUT4 | 14857 | 14683（−174） |
| FF | 4040 | 4035（−5） |
| BRAM | 195 | 195 |
| DSP48 | 100 | 100 |
| ADD / SRL8 | 255 / 134 | 257 / 134 |
| setup slack | 1.809 ns | **0.539 ns** |
| hold slack | 0.026 ns | **0.026 ns** |
| 当前布线分析的最小周期 | 8.191 ns | **6.128 ns** |

生成的 SDC 周期为 `6.666667 ns`；Efinity 报告按 `6.667 ns / 149.993 MHz` 显示。独立的 150 MHz 重新综合、布局布线得到相同余量。默认综合约束已改为 150 MHz。

最终关键路径仍是 `d1_owner[2] → windows/bank[1].ram/WDATAA[0]`，包含窗口装载时的行选择和 bank 重排，逻辑级数 13；在目标周期内收敛。报告针对内部同步路径，未约束板级 I/O，未进行板上验证。

可写参数顶层 `mobilenet_bus_top` 也独立通过 150 MHz：setup / hold 为 **0.966 / 0.026 ns**，14649 LUT4、4023 FF、178 BRAM、100 DSP48。主结果仍按包含 epoch11 全部参数的固定模型顶层统计。

## 为什么先收紧约束

原工程的约束是 100 MHz，布局布线在满足 10 ns 后即可停止优化。其报告中的 122.085 MHz 是那一次布线的分析结果，并不能直接作为 RTL 的最高可实现频率。

实际对照如下，全部为布局布线后的结果：

| 实验 | 约束 | setup / hold | LUT4 / FF | 空间核额外拍数 |
|---|---:|---:|---:|---:|
| 原 RTL | 200 MHz | 0.143 / 0.026 ns | 14857 / 4040 | 0 |
| 窗口写入增加流水线 | 200 MHz | 0.098 / 0.026 ns | 14812 / 4214 | 无填充 +10；每边再 +3 |
| 参数 ROM 输出清零＋OR | 200 MHz | 0.089 / 0.028 ns | 14683 / 4035 | 0 |
| 最终参数 ROM 方案 | **150 MHz** | **0.539 / 0.026 ns** | **14683 / 4035** | **0** |

窗口试验通过了 327100 次像素检查及六指令跟踪，但增加装载时间，且整核 200 MHz 余量没有改善，因此未保留。最终采用原窗口控制和数据通路。200 MHz 的 ROM 方案将关键路径移到量化/池化；按用户调整后的目标，没有继续增加后处理流水级。

不同目标会导致布局布线选择不同，150 MHz 布线的分析 Fmax 为 163.185 MHz，而 200 MHz 对照为 203.625 MHz。这些值均对应各自的布线结果。

## ROM 改动：利用已有 BRAM 输出锁存器

原 compact 参数 ROM 用 `low_bank` 从 22 个 10 bit BRAM 输出中选择，再与高位和稀疏例外合并，进入权重偏置舍入加法器，最后广播到 100 个 DSP。

本轮保留 25 个参数 BRAM 和原始 Q8.8 初始化数据：

1. `rd_en=1` 时，命中的 bank 正常读取；其他 bank 用原语 `RESET_RAM="SYNC"` 将输出锁存器清零。
2. 所有 low bank 输出做 OR，高位 bank 同样做 OR。只有命中的 bank 可以非零，因此直接得到选中参数。
3. 稀疏例外的判断、数据和优先级保持原样。
4. `rd_en=0` 时全部 BRAM 的 RE 为零，同步复位也不生效，数据继续保持。

利用的是 BRAM 已有的输出锁存器，没有增加 fabric 数据寄存器或读延迟。权重读取仍为一拍。原语模型、综合网表与 RTL 都检查了连续读、bank 跳转及停读保持。导出工具也改为只更新初始化数据和 Tanh 表，避免重新导出模型时覆盖优化后的 RTL。

## 执行时间保持

E 从 FIFO 弹出沿到 done 沿计算，不包含主机传输及排队等待。

| 指令，正常输出、无填充 | E | 150 MHz 时间 |
|---|---:|---:|
| PW，无舍入，Cin=1 | 9 | 60 ns |
| PW，无舍入，Cin=32 | 40 | 267 ns |
| NORM / ADD，无舍入 | 10 | 67 ns |
| 3×3 DW | 77 | 513 ns |
| 7×7 DW | 117 | 780 ns |

空间核公式仍为 `E = 核面积 + 68 + 9×需要修补的边数`，raw 减 1，Tanh 加 54。PW 仍每拍接收一个通道，3×3 / 7×7 DW 的 9 / 49 次 MAC 连续，排队切换仍为一拍（约 6.67 ns）。相同指令在 150 MHz 下用时为原 100 MHz 的 2/3。

## 复现

```powershell
./scripts/run_synthesis.ps1 -Top cyclegan_bus_top -ClockMHz 150
./scripts/run_pnr.ps1
./scripts/run_sim.ps1 -Jobs 8
./scripts/run_cyclegan_checks.ps1
python tools/record_cyclegan_results.py
```

`run_pnr.ps1` 现在读取 STA 报告并要求 setup、hold 都非负，避免把工具的流程 PASS 当成时序收敛。

独立对照可用 `./scripts/run_timing_sweep.ps1 -Frequencies 150,200`；可写参数顶层可加 `-Top mobilenet_bus_top`。各次运行在独立 ASCII 临时目录中完成，报告保存到 `build/timing/<top>/<MHz>`，不会覆盖生产网表和报告。

## 验证

最终 RTL 与生产综合目录逐文件哈希一致，以下本轮检查均通过：

- 完整 RTL 回归：201 用例、252 指令、29924 测试周期，含 9 条预期错误；全部指令的拍数匹配周期模型。
- 六指令逐沿跟踪：3×3 / 7×7 为 77 / 117 拍，四条单通道 PW 各 9 拍；MAC 顺序、连续性、last 标签及一拍排队切换正确，合计 429 测试周期。
- 实际 epoch11 的 RTL 和整核综合网表各 6 指令，逐字节一致，均为 1006 测试周期，包含 7×7 CONV/Tanh、反射补边、第三 bank 和扩展参数。
- 22016 个 ROM 地址、256 次跨 bank 跳转与停读保持、4096 个 Tanh 地址及极值；八 bank 窗口 327100 次像素检查；后处理 205800 次检查；FIFO RTL/综合网表、输入 mux 和 compact 专项检查。
- 总线黄金结果、背压、中途复位、bank2 行掩码和非法地址隔离；cache RTL 4279 全字检查。
- 固定模型与可写参数顶层的 150 MHz setup / hold 均通过；STA 检查器的负 setup、负 hold 对照都会报错。

独立 cache 综合网表检查复用上一轮的 4279 次结果，重新核对未改动的 cache RTL、测试源和网表哈希；旧寄存器窗口测试仅作为历史参考。

验证详情及源码、网表、报告哈希记录在 [`analysis/cyclegan_iteration9_results.json`](analysis/cyclegan_iteration9_results.json)。整网的两帧整数指令模型沿用上一轮结果；本轮未做整帧 RTL 或板上推理验证。
